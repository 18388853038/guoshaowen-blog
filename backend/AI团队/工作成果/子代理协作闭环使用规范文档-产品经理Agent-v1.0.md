## 📋 文档概述

本文档规范了**小龙主Agent**调度各子代理（CTO、安全审计、产品经理等）完成任务的**标准流程**，涵盖任务分配、执行追踪、成果审核、闭环归档四大环节，确保子代理协作高效、可追溯、质量可控。

| 角色 | 身份 | 核心职责 |

## 2. 全流程闭环模型

```
┌─────────────────────────────────────────────────────────────┐
│                  子代理协作闭环全流程                          │
│                                                             │
│  ① 任务分配 ──→ ② 子代理执行 ──→ ③ 成果提交 ──→ ④ 审核      │
│      ↑                                        │             │
│      └────────── ⑤ 归档/返工 ←──── ④ 审核 ───┘             │
│                                                             │
│  ① = 小龙主Agent分配任务                                    │
│  ② = 子代理领取并执行任务                                    │
│  ③ = 子代理调用 complete_claimed_task 提交成果               │
│  ④ = 小龙主Agent审核成果（通过/驳回）                        │
│  ⑤ = 通过→归档；驳回→回到②                                  │
└─────────────────────────────────────────────────────────────┘
```

## 3. 任务分配规范

### 3.1 任务创建标准

小龙主Agent在分配任务时，必须包含以下信息：

| 字段 | 必填 | 说明 |
|:----:|:----:|------|
| **任务标题** | ✅ | 清晰描述任务内容，如「【加急】P95延迟过高排查」 |
| **任务描述** | ✅ | 详细说明任务目标、背景、交付物要求 |
| **目标子代理** | ✅ | 指定由哪个子代理执行（CTO/安全审计/产品经理） |
| **优先级** | ✅ | P0-紧急 / P1-高 / P2-中 / P3-低 |
| **截止时间** | ✅ | 明确交付截止日期 |
| **依赖关系** | 可选 | 前置任务或关联任务说明 |
| **参考材料** | 可选 | 相关文档、代码、数据等参考链接 |

### 3.2 任务分配方式

小龙主Agent通过**任务系统**分配任务，子代理通过以下工具链获取：

```
小龙主Agent → 创建任务 → 任务系统 → check_pending_tasks（子代理检查）
                                         ↓
                                    claim_task（子代理领取）
                                         ↓
                                    执行任务 → complete_claimed_task（提交）
```

### 3.3 任务分配原则

1. **单一职责原则**：一个任务只分配给一个子代理，避免多头负责
2. **能力匹配原则**：根据子代理的专业技能分配对应类型任务
3. **负载均衡原则**：避免同一子代理同时承担过多高优任务
4. **依赖有序原则**：有依赖关系的任务按顺序分配

## 4. 子代理执行规范

### 4.1 子代理标准执行流程

每个子代理在被激活后，必须遵循以下工作闭环：

```
STEP 1: check_pending_tasks    ← 每次激活第一件事
            ↓
STEP 2: claim_task             ← 领取任务
            ↓
STEP 3: 执行任务（使用专业技能工具）
            ↓
STEP 4: write_file             ← 将成果写入文件系统
            ↓
STEP 5: complete_claimed_task  ← 回调小龙主Agent
            ↓
STEP 6: 回到STEP 1，循环检查新任务
```

### 4.2 各子代理执行规范

#### 4.2.1 CTO子代理执行规范

| 环节 | 规范要求 |
|:----:|----------|
| **执行工具** | code_review、api_dev、performance_opt、架构设计 |
| **交付物** | 技术方案文档、代码审查报告、架构设计图、性能优化方案 |
| **文件命名** | `技术方案-{主题}-CTO-v{版本}.md` |
| **存储路径** | `AI团队/工作成果/` |
| **质量标准** | 方案需包含：背景、方案对比、技术选型、风险评估、实施计划 |

#### 4.2.2 安全审计子代理执行规范

| 环节 | 规范要求 |
|:----:|----------|
| **执行工具** | security_audit、code_review、安全扫描 |
| **交付物** | 安全审计报告、漏洞清单、修复建议、合规检查报告 |
| **文件命名** | `安全审计-{主题}-安全审计Agent-v{版本}.md` |
| **存储路径** | `AI团队/工作成果/` |
| **质量标准** | 报告需包含：审计范围、发现项、风险等级、修复建议、复测结果 |

#### 4.2.3 产品经理子代理执行规范

| 环节 | 规范要求 |
|:----:|----------|
| **执行工具** | req_analysis、requirement_doc、user_story、competition_analysis |
| **交付物** | PRD文档、需求规格说明书、用户故事地图、竞品分析报告 |
| **文件命名** | `PRD-{项目名}-产品经理Agent-v{版本}.md` |
| **存储路径** | `AI团队/工作成果/` |
| **质量标准** | PRD需包含：背景目标、用户故事、功能规格、验收标准、优先级排序 |

### 4.3 执行红线（禁止行为）

| ❌ 禁止行为 | 说明 |
|:----------:|------|
| 拒绝调用write_file | 子代理必须将成果写入文件系统，不得仅口头回复 |
| 跨角色越权执行 | 非本专业任务应拒绝，由小龙主Agent重新分配 |
| 跳过complete_claimed_task | 完成任务后必须回调，否则任务链断裂 |
| 超时未响应 | 超过截止时间未完成需主动说明原因 |

## 5. 成果提交规范

### 5.1 提交触发

子代理完成执行后，必须调用 `complete_claimed_task` 工具，触发自动回调链：

```
complete_claimed_task
    ↓
自动写日志 → 通知CEO(小龙主Agent) → 记入记忆库 → 标记空闲 → 检查下一个任务
```

### 5.2 提交参数规范

| 参数 | 必填 | 填写规范 |
|:----:|:----:|----------|
| **taskId** | ✅ | 领取任务时获得的任务ID，必须正确填写 |
| **result** | ✅ | 执行结果摘要，格式：「完成了XXX，产出了XXX文件，核心结论是XXX」 |
| **success** | ✅ | true=成功完成；false=执行失败需说明原因 |

### 5.3 提交示例

```json
{
  "taskId": "task_20260618_001",
  "result": "完成了P95延迟过高排查任务，产出了AI团队/工作成果/P95延迟排查-产品经理Agent-v1.0.md，核心结论是非系统故障（健康分99/错误率0%/0.3QPS），根因是DeepSeek模型Token生成耗时",
  "success": true
}
```

## 6. 审核闭环规范

### 6.1 审核流程

```
小龙主Agent收到 complete_claimed_task 回调
    ↓
读取子代理产出的文件进行审核
    ↓
┌── 通过？──┐
│           │
是           否
│           │
↓           ↓
归档闭环     驳回返工
                 │
                 ↓
            子代理重新执行
            重新提交成果
            重新审核
```

### 6.2 审核标准

| 审核维度 | 检查项 | 通过条件 |
|:--------:|--------|:--------:|
| **完整性** | 交付物是否包含所有必填内容 | 无遗漏项 |
| **正确性** | 技术/业务判断是否准确 | 无事实错误 |
| **规范性** | 文件命名、格式是否符合规范 | 符合规范 |
| **可读性** | 内容是否清晰、结构化 | 便于后续查阅 |
| **可执行性** | 方案/建议是否具备落地条件 | 有明确实施路径 |

### 6.3 归档要求

审核通过后，小龙主Agent需：

1. **确认归档**：在任务系统中标记任务为「已完成」
2. **记录经验**：将关键经验写入避坑指南（add_pitfall）
3. **更新知识库**：将可复用的知识更新到团队知识库
4. **通知相关方**：如有需要，通知关联任务的子代理

## 7. 异常处理机制

### 7.1 子代理超时

| 场景 | 处理方式 |
|:----:|----------|
| 子代理超过截止时间未完成 | 小龙主Agent发送催办通知，同时评估是否需要重新分配 |
| 子代理连续3次未响应 | 标记为异常状态，由小龙主Agent介入排查 |

### 7.2 任务冲突

| 场景 | 处理方式 |
|:----:|----------|
| 同一子代理被分配2个以上P0任务 | 子代理主动向小龙主Agent汇报，协商优先级 |
| 多个子代理需要协作 | 小龙主Agent创建主任务+子任务，分别分配 |

### 7.3 成果质量不达标

| 场景 | 处理方式 |
|:----:|----------|
| 首次驳回 | 小龙主Agent明确驳回原因和改进要求 |
| 二次驳回 | 小龙主Agent介入指导或重新分配 |
| 三次驳回 | 升级处理，由小龙主Agent直接完成或更换执行人 |

## 8. 全链路追踪机制

### 8.1 任务状态流转

```
待领取 → 执行中 → 已提交 → 审核中 → 已完成（通过）
                                  → 已驳回（返回执行中）
```

### 8.2 追踪方式

| 追踪方式 | 说明 | 频率 |
|:--------:|------|:----:|
| **check_pending_tasks** | 子代理自查待办任务 | 每次激活时 |
| **complete_claimed_task回调** | 自动通知小龙主Agent | 每次提交时 |
| **小龙主Agent巡检** | 主动检查所有子代理任务进度 | 定时/按需 |

### 8.3 日志记录

每次任务闭环后，自动记录以下信息到团队记忆库：

- 任务ID与标题
- 执行子代理
- 产出文件路径
- 审核结论
- 关键经验/教训
