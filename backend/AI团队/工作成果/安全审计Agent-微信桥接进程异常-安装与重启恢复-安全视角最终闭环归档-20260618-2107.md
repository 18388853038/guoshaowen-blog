在执行安装与重启之前，安全审计Agent进行了以下安全检查：

| 依赖完整性 | 检查 Node.js/Python 依赖包 | ✅ 依赖完整 | 🟢 低危 |

### 第二阶段：安全安装流程

#### 步骤 1：环境清理（安全加固）
```bash
# 1. 安全终止残留进程
kill -9 $(cat /var/run/wechat-bridge.pid 2>/dev/null) 2>/dev/null
rm -f /var/run/wechat-bridge.pid

# 2. 确认端口已释放
lsof -i :8080 | grep -q wechat-bridge && echo "端口仍被占用" || echo "端口已释放"

# 3. 清理僵尸进程
ps aux | grep defunct | grep -v grep && echo "存在僵尸进程需清理" || echo "无僵尸进程"
```

#### 步骤 2：依赖安装（带安全校验）
```bash
# 1. 进入项目目录
cd /opt/wechat-bridge/

# 2. 安装依赖（使用package-lock.json确保版本一致性）
npm ci --only=production 2>&1

# 3. 安全校验：检查依赖是否存在已知漏洞
npm audit --production 2>&1 || echo "⚠️ 存在已知漏洞，建议修复"
```

#### 步骤 3：配置文件安全加固
```bash
# 1. 检查配置文件权限
ls -la config/wechat-config.json
# 预期：-rw------- (600) 或 -rw-r----- (640)

# 2. 检查API密钥是否硬编码
grep -r "sk-" config/ 2>/dev/null && echo "⚠️ API密钥明文存储" || echo "✅ 密钥已通过环境变量管理"

# 3. 检查日志配置
grep -i "log\|rotate\|maxSize" config/*.json 2>/dev/null
```

### 第三阶段：安全重启流程

#### 步骤 1：启动前安全验证
```bash
# 1. 语法检查
node -c app.js 2>&1

# 2. 端口可用性检查
ss -tlnp | grep -q :8080 && echo "端口被占用" || echo "端口可用"

# 3. 环境变量检查
env | grep -E "WECHAT|API_KEY|TOKEN" | wc -l
```

#### 步骤 2：安全启动
```bash
# 1. 使用nohup启动（带日志重定向）
nohup node app.js > logs/wechat-bridge-$(date +%Y%m%d-%H%M%S).log 2>&1 &
echo $! > /var/run/wechat-bridge.pid

# 2. 等待启动完成
sleep 3

# 3. 验证进程存活
if kill -0 $(cat /var/run/wechat-bridge.pid) 2>/dev/null; then
    echo "✅ 进程启动成功"
else
    echo "❌ 进程启动失败，检查日志"
fi
```

#### 步骤 3：启动后安全验证
```bash
# 1. 健康检查
curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/health

# 2. 检查日志是否正常输出
tail -5 logs/wechat-bridge-*.log | head -5

# 3. 资源占用检查
ps -p $(cat /var/run/wechat-bridge.pid) -o %cpu,%mem,rss,vsz --no-headers
```

### 第四阶段：安全加固建议（安装后）

| 序号 | 安全加固项 | 严重度 | 实施方式 |
|:---:|:----------|:------:|:---------|
| 1️⃣ | **配置systemd守护进程** | 🔴 高危 | 创建 `/etc/systemd/system/wechat-bridge.service`，实现进程自愈 |
| 2️⃣ | **API密钥迁移至环境变量** | 🔴 高危 | 从配置文件中移除明文密钥，改用 `.env` 文件 + 环境变量 |
| 3️⃣ | **日志轮转配置** | 🟡 中危 | 配置 logrotate，限制日志文件大小和保留天数 |
| 4️⃣ | **添加健康检查端点** | 🟡 中危 | 在 Express/Fastify 中添加 `/health` 端点 |
| 5️⃣ | **进程监控告警** | 🟡 中危 | 配置定时任务每5分钟检查进程存活状态 |
