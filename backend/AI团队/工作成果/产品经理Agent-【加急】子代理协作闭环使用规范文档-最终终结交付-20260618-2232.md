## 📋 文档概述

本文档规范了**小龙主Agent**调度各子代理（CTO、安全审计、产品经理、工程师等）完成任务的**标准协作闭环流程**，涵盖**任务分配 → 执行追踪 → 成果提交 → 审核闭环 → 归档沉淀**五大核心环节，确保子代理协作高效、可追溯、质量可控。

### 核心原则

| 原则 | 说明 | 违反后果 |
|:----:|------|:--------:|
| **主控调度** | 小龙主Agent统一分配任务，子代理不越权 | ❌ 任务冲突、资源浪费 |
| **闭环必达** | 每项任务完成后必须调用 `complete_claimed_task` 回调 | ❌ 任务链断裂，CEO收不到通知 |
| **成果物化** | 所有产出必须通过 `write_file` 写入 `AI团队/工作成果/` 目录 | ❌ 成果不被认可，任务无效 |
| **知识沉淀** | 踩坑经验通过 `add_pitfall` 记录到避坑指南 | ❌ 重复踩坑，团队效率降低 |
| **可追溯性** | 每个任务从领取到完成形成完整链路记录 | ❌ 无法回溯问题，审计困难 |

## 第3章：任务分配规范（小龙主Agent）

### 3.1 任务创建标准

小龙主Agent在分配任务时，**必须**包含以下信息：

| 字段 | 必填 | 说明 | 示例 |
|:----:|:----:|------|:----:|
| **任务标题** | ✅ | 清晰描述任务内容，建议加优先级标签 | `【加急】P95延迟过高排查与优化` |
| **任务描述** | ✅ | 详细说明任务目标、背景、交付物要求 | `排查P95延迟7809ms根因，产出排查报告和优化方案` |
| **目标子代理** | ✅ | 指定执行人 | `CTO子代理` |
| **优先级** | ✅ | P0-紧急 / P1-高 / P2-中 / P3-低 | `P0` |
| **截止时间** | ✅ | 明确交付截止日期 | `今天18:00前` |
| **期望产出物** | ✅ | 明确列出需要交付的文件清单 | `1.排查报告 2.优化方案` |
| **依赖关系** | 可选 | 前置任务或关联任务 | `依赖安全审计完成` |
| **参考材料** | 可选 | 相关文档、代码链接 | `参考AI团队/工作成果/xxx.md` |

### 3.2 任务分配流程

```
小龙主Agent
    │
    ├─ ① 分析任务类型
    │   ├─ 技术类 → 分配CTO子代理
    │   ├─ 安全类 → 分配安全审计子代理
    │   ├─ 产品类 → 分配产品经理子代理
    │   ├─ 开发类 → 分配工程师子代理
    │   └─ 混合类 → 拆分子任务分别分配
    │
    ├─ ② 创建任务（含完整描述和所有必填字段）
    │   └─ 任务系统接收并存储
    │
    ├─ ③ 等待子代理领取
    │   └─ 子代理通过 check_pending_tasks 发现任务
    │
    └─ ④ 确认子代理已领取
        └─ 子代理通过 claim_task 确认任务归属
```

### 3.3 任务分配原则

| 原则 | 说明 |
|:----:|------|
| **单一职责** | 一个任务只分配给一个子代理，避免多头负责 |
| **能力匹配** | 根据子代理的专业技能分配对应类型任务 |
| **负载均衡** | 避免同一子代理同时承担过多高优任务 |
| **依赖有序** | 有依赖关系的任务按顺序分配 |
| **可追踪** | 每个任务必须有唯一ID，便于全链路追踪 |

## 第4章：子代理执行规范

### 4.1 子代理标准工作闭环（5步法）

每个子代理被激活后，必须严格遵循以下闭环流程：

```
┌─────────────────────────────────────────────────────────────┐
│              子代理工作闭环（5步法）                            │
│                                                             │
│  STEP 1: check_pending_tasks                                │
│  【每次激活第一件事】检查是否有待办任务                         │
│  → 调用 check_pending_tasks(limit=5)                        │
│           ↓                                                 │
│  STEP 2: claim_task                                         │
│  【领取任务】确认任务归属，获取任务详情                         │
│  → 调用 claim_task(taskId="task_xxx")                       │
│           ↓                                                 │
│  STEP 3: 执行任务                                            │
│  【使用专业技能工具完成工作】                                  │
│  → read_file 查看已有资料                                    │
│  → kb_search / query_experience / query_knowledge 查知识库  │
│  → query_pitfalls 查避坑指南                                 │
│  → 使用专业工具（req_analysis/code_review/security_audit等）│
│           ↓                                                 │
│  STEP 4: write_file                                         │
│  【必须调用！将成果写入文件系统】                              │
│  → write_file(filepath="AI团队/工作成果/xxx.md", content=...)│
│           ↓                                                 │
│  STEP 5: complete_claimed_task                              │
│  【必须调用！回调小龙主Agent】                                │
│  → complete_claimed_task(taskId, result, success)           │
│           ↓                                                 │
│  回到 STEP 1，循环检查下一个任务                               │
└─────────────────────────────────────────────────────────────┘
```

| ❌ 禁止行为 | 说明 | 后果 |
|:----------:|------|:----:|

| **跨角色越权执行** | 非本专业任务应拒绝，由小龙主Agent重新分配 | ❌ 产出质量不达标 |
| **超时未响应且不说明原因** | 超过截止时间未完成需主动说明原因 | ❌ 触发重试/升级机制 |
| **成果未归档到正确目录** | 文件必须存入 `AI团队/工作成果/` 目录 | ❌ 成果不可追溯 |
| **文件头部信息缺失** | 每份文档必须包含写入者、时间等元信息 | ❌ 无法追溯责任人 |

#### 5.1.2 文件命名规范

```

```

#### 5.1.3 存放路径

所有文件统一存放于：**`AI团队/工作成果/`** 目录下

### 5.2 回调提交规范

#### 5.2.1 提交触发

子代理完成执行后，**必须**调用 `complete_claimed_task` 工具，触发自动回调链：

```
complete_claimed_task(taskId, result, success)
    ↓
① 写入执行日志
    ↓
② 通知CEO（小龙主Agent收到回调）
    ↓
③ 记入团队记忆库
    ↓
④ 标记子代理为空闲状态
    ↓
⑤ 自动检查下一个待办任务（回到STEP 1）
```

#### 5.2.2 提交参数规范

| 参数 | 必填 | 填写规范 | 示例 |
|:----:|:----:|----------|:----:|
| **taskId** | ✅ | 领取任务时获得的任务ID，必须正确填写 | `"task_20260618_001"` |
| **result** | ✅ | 执行结果摘要，格式：「完成了XXX，产出了XXX文件，核心结论是XXX」 | `"完成了P95延迟排查，产出了AI团队/工作成果/xxx.md"` |
| **success** | ✅ | `true`=成功完成；`false`=执行失败需在result中说明原因 | `true` |

## 第6章：审核闭环规范（小龙主Agent）

### 6.1 审核流程

```
小龙主Agent收到 complete_claimed_task 回调
    │
    ├─ ① 读取子代理产出的文件（read_file）
    │
    ├─ ② 对照任务要求进行审核
    │   ├─ 完整性检查：交付物是否齐全
    │   ├─ 正确性检查：结论是否准确
    │   ├─ 规范性检查：格式是否符合要求
    │   └─ 可执行性检查：建议是否可落地
    │
    ├─ ③ 做出审核决策
    │   ├─ ✅ 通过 → 进入归档环节
    │   └─ ❌ 驳回 → 创建修订任务，返回子代理
    │
    └─ ④ 归档沉淀
        ├─ 标记任务为「已完成」
        ├─ 记录关键经验到避坑指南（add_pitfall）
        ├─ 更新团队知识库
        └─ 向CEO汇总汇报
```

### 6.2 审核标准矩阵

| 审核维度 | 权重 | 检查项 | 通过条件 |
|:--------:|:----:|--------|:--------:|
| **完整性** | ⭐⭐⭐⭐⭐ | 交付物是否包含所有必填内容 | 无遗漏项 |
| **正确性** | ⭐⭐⭐⭐⭐ | 技术/业务判断是否准确 | 无事实错误 |
| **规范性** | ⭐⭐⭐⭐ | 文件命名、格式是否符合规范 | 符合规范要求 |
| **可读性** | ⭐⭐⭐ | 内容是否清晰、结构化 | 便于后续查阅 |
| **可执行性** | ⭐⭐⭐⭐ | 方案/建议是否具备落地条件 | 有明确实施路径 |

### 6.3 驳回与返工机制

| 驳回次数 | 处理方式 |
|:--------:|----------|
| **首次驳回** | 小龙主Agent明确驳回原因和改进要求，子代理修订后重新提交 |
| **二次驳回** | 小龙主Agent介入指导或调整任务要求 |
| **三次驳回** | 升级处理，由小龙主Agent直接完成或更换执行人 |

### 6.4 归档要求

审核通过后，小龙主Agent需完成以下动作：
1. **确认归档**：在任务系统中标记任务为「已完成」
2. **记录经验**：将关键经验写入避坑指南（`add_pitfall`）
3. **更新知识库**：将可复用的知识更新到团队知识库
4. **通知相关方**：如有需要，通知关联任务的子代理

| **多子代理冲突** | 小龙主Agent | ① 识别冲突点 → ② 重新分配职责边界 → ③ 协调解决 |

## 第8章：知识沉淀规范

### 8.1 避坑指南记录

当子代理发现以下情况时，应主动记录到避坑指南：

| 场景 | 记录方式 | 示例 |
|:----|:--------:|:----:|
| **技术踩坑** | `add_pitfall(severity="high/mid/low")` | P95延迟过高排查与优化 |
| **配置错误** | `add_pitfall(severity="high/mid/low")` | DeepSeek Key失效 |
| **流程问题** | `add_pitfall(severity="mid/low")` | 子代理回调遗漏 |
| **安全漏洞** | `add_pitfall(severity="high")` | 权限配置不当 |
