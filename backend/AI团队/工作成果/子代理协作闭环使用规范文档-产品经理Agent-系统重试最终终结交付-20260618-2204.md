## 三、标准协作流程

### 3.1 任务分配阶段

```
小龙主Agent
    │
    ├── 技术类任务 ──→ CTO-Agent（技术方案/代码实现/性能优化）
    │
    ├── 安全类任务 ──→ 安全审计Agent（安全审查/风险评估）
    │
    └── 文档类任务 ──→ 产品经理Agent（需求文档/规范编写）
```

**分配规则**：
1. 小龙根据任务类型选择对应子代理
2. 通过任务系统分配（系统自动创建待办任务）
3. 子代理通过 `check_pending_tasks` 检查待办
4. 子代理通过 `claim_task` 领取任务

### 3.2 执行追踪阶段

```
子代理领取任务
    │
    ├── 读取相关文件（read_file / list_directory）
    ├── 查询知识库/经验库（kb_search / query_experience）
    ├── 执行核心工作（代码编写/文档编写/安全审查）
    ├── 产出交付物（write_file → 写入 AI团队/工作成果/）
    └── 回调完成（complete_claimed_task → 通知小龙）
```

**追踪机制**：
- 每个子代理在执行过程中通过 `write_file` 产出中间成果
- 文件统一存放于 `AI团队/工作成果/` 目录
- 文件名规范：`{任务描述}-{子代理名称}-{版本号}.md`

### 3.3 审核验收阶段

```
子代理完成回调
    │
    ├── 小龙主Agent审核交付物
    │   ├── 质量达标 → 进入归档
    │   └── 需要修改 → 重新分配任务
    │
    └── 审核标准：
        ├── 交付物完整性（文件是否存在/内容是否完整）
        ├── 职责边界清晰（是否在职责范围内）
        └── 质量达标（逻辑清晰/方案可行/无错误）
```

### 3.4 闭环归档阶段

```
审核通过
    │
    ├── 交付物归档（保留在 AI团队/工作成果/ 目录）
    ├── 经验入库（add_pitfall → 记录踩坑经验）
    ├── 知识入库（query_knowledge → 更新知识库）
    └── 任务标记完成（complete_claimed_task → 最终闭环）
```

## 五、重试机制处理规范

### 5.1 重试通知识别

当系统发出重试通知时，子代理应：
1. **先核查**：检查 `AI团队/工作成果/` 目录是否已有交付物
2. **再判断**：如果已有闭环交付物 → 输出终结声明，无需重复执行
3. **后执行**：如果确实未完成 → 重新执行任务

### 5.2 重试终结流程

```
收到重试通知
    │
    ├── check_pending_tasks → 查看待办
    ├── list_directory → 检查已有交付物
    │
    ├── 已有交付物 → write_file 输出终结声明
    │               → complete_claimed_task 提交
    │
    └── 无交付物 → 正常执行任务
                  → write_file 产出交付物
                  → complete_claimed_task 提交
```
