## 3. 任务分配规范（小龙主Agent）

### 3.1 任务创建标准

小龙主Agent创建任务时，必须包含以下字段：

| 字段 | 必填 | 说明 | 示例 |
|:----:|:----:|------|:----:|
| **任务标题** | ✅ | 清晰描述任务内容，建议加优先级标签 | `【加急】P95延迟过高排查与优化` |
| **任务描述** | ✅ | 详细说明任务目标、背景、交付要求 | `排查P95延迟7809ms根因...` |
| **目标子代理** | ✅ | 指定执行人 | `CTO子代理` |
| **优先级** | ✅ | P0-紧急 / P1-高 / P2-中 / P3-低 | `P0` |
| **截止时间** | ✅ | 明确交付截止日期 | `今天18:00前` |
| **期望产出物** | ✅ | 明确列出需要交付的文件清单 | `1.排查报告 2.优化方案` |
| **依赖关系** | 可选 | 前置任务或关联任务 | `依赖安全审计完成` |
| **参考材料** | 可选 | 相关文档、代码链接 | `参考AI团队/工作成果/...` |

### 3.2 任务分配流程

```
小龙主Agent
    │
    ├─ ① 分析任务类型
    │   ├─ 技术类 → 分配CTO子代理
    │   ├─ 安全类 → 分配安全审计子代理
    │   ├─ 产品类 → 分配产品经理子代理
    │   └─ 混合类 → 拆分子任务分别分配
    │
    ├─ ② 创建任务（含完整描述）
    │
    ├─ ③ 等待子代理领取（通过check_pending_tasks）
    │
    └─ ④ 确认子代理已领取（通过claim_task回调）
```

### 3.3 分配原则

| 原则 | 说明 |
|:----:|------|
| **单一职责** | 一个任务只分配给一个子代理，避免多头负责 |
| **能力匹配** | 根据子代理的专业技能分配对应类型任务 |
| **负载均衡** | 避免同一子代理同时承担过多高优任务 |
| **依赖有序** | 有依赖关系的任务按顺序分配 |
| **可追踪** | 每个任务必须有唯一ID，便于全链路追踪 |

## 4. 子代理执行规范

每个子代理被激活后，必须严格遵循以下闭环流程：

```
┌─────────────────────────────────────────────┐

│                                             │
│  STEP 1: check_pending_tasks                │
│  【每次激活第一件事】检查是否有待办任务        │
│           ↓                                 │
│  STEP 2: claim_task                         │
│  【领取任务】确认任务归属，获取任务详情        │
│           ↓                                 │
│  STEP 3: 执行任务                            │
│  【使用专业技能工具完成工作】                  │
│  - read_file 查看已有资料                    │
│  - kb_search / query_experience 查知识库     │
│  - 使用专业工具（req_analysis/code_review等）│
│           ↓                                 │
│  STEP 4: write_file                         │
│  【必须调用！将成果写入文件系统】             │
│  路径：AI团队/工作成果/                      │
│           ↓                                 │
│  STEP 5: complete_claimed_task              │
│  【必须调用！回调小龙主Agent】               │
│  参数：taskId + result + success            │
│           ↓                                 │
│  回到 STEP 1，循环检查下一个任务              │
└─────────────────────────────────────────────┘
```

| ❌ 禁止行为 | 说明 | 后果 |
|:----------:|------|:----:|

## 6. 审核闭环规范（小龙主Agent）

### 6.1 审核流程

```
小龙主Agent收到 complete_claimed_task 回调
    │
    ├─ ① 读取子代理产出的文件（read_file）
    │
    ├─ ② 对照任务要求进行审核
    │   ├─ 完整性检查：交付物是否齐全
    │   ├─ 正确性检查：结论是否准确
    │   ├─ 规范性检查：格式是否符合要求
    │   └─ 可执行性检查：建议是否可落地
    │
    ├─ ③ 做出审核决策
    │   ├─ ✅ 通过 → 进入归档环节
    │   └─ ❌ 驳回 → 创建修订任务，返回子代理
    │
    └─ ④ 归档沉淀
        ├─ 标记任务为「已完成」
        ├─ 记录关键经验到避坑指南（add_pitfall）
        ├─ 更新团队知识库
        └─ 向CEO汇总汇报
```

### 6.2 审核标准矩阵

| 审核维度 | 权重 | 检查项 | 通过条件 |
|:--------:|:----:|--------|:--------:|
| **完整性** | ⭐⭐⭐ | 交付物是否包含所有必填内容 | 无遗漏项 |
| **正确性** | ⭐⭐⭐ | 技术/业务判断是否准确 | 无事实错误 |
| **规范性** | ⭐⭐ | 文件命名、格式是否符合规范 | 符合规范 |
| **可读性** | ⭐⭐ | 内容是否清晰、结构化 | 便于后续查阅 |
| **可执行性** | ⭐⭐⭐ | 方案/建议是否具备落地条件 | 有明确实施路径 |

### 6.3 闭环归档要求

审核通过后，小龙主Agent需完成以下归档工作：

1. **标记完成**：在任务系统中标记任务为「已完成」
2. **经验沉淀**：将关键经验通过 `add_pitfall` 写入避坑指南
3. **知识更新**：将可复用的知识通过 `query_knowledge` 相关接口更新到团队知识库
4. **汇总汇报**：整合所有子代理成果，向CEO汇报
5. **通知相关方**：如有需要，通知关联任务的子代理

---

## 7. 异常处理机制

### 7.1 任务超时/卡住

| 异常场景 | 处理方式 | 触发条件 |
|:--------:|----------|:--------:|
| **子代理长时间未响应** | 小龙主Agent发送重试通知 | 超过截止时间 |
| **子代理执行失败** | 在 `complete_claimed_task` 中设置 `success=false` 并说明原因 | 执行过程中出现不可抗力 |
| **连续3次重试失败** | 小龙主Agent接管任务，手动处理 | 第3次失败后 |
| **工具调用异常** | 记录到避坑指南，尝试替代方案 | 工具返回错误 |

### 7.2 成果质量不达标

| 驳回次数 | 处理方式 |
|:--------:|----------|
| **首次驳回** | 小龙主Agent明确驳回原因和改进要求，创建修订任务 |
| **二次驳回** | 小龙主Agent介入指导，提供具体修改建议 |
| **三次驳回** | 升级处理，由小龙主Agent直接完成或更换执行人 |

### 7.3 任务冲突

| 场景 | 处理方式 |
|:----:|----------|
| 同一子代理被分配2个以上P0任务 | 子代理主动向小龙主Agent汇报，协商优先级 |
| 多个子代理需要协作 | 小龙主Agent创建主任务+子任务，分别分配 |
| 任务依赖链断裂 | 小龙主Agent协调上下游子代理，重新排期 |

## 8. 全链路追踪机制

### 8.1 任务状态流转

```
待领取 ──→ 执行中 ──→ 已提交 ──→ 审核中 ──→ 已完成（通过）
                              └─→ 已驳回 ──→ 执行中（返工）
```

### 8.2 追踪方式

| 追踪方式 | 说明 | 执行方 | 频率 |
|:--------:|------|:------:|:----:|
| **check_pending_tasks** | 子代理自查待办任务 | 子代理 | 每次激活时 |
| **complete_claimed_task回调** | 自动通知小龙主Agent | 系统自动 | 每次提交时 |
| **小龙主Agent巡检** | 主动检查所有子代理任务进度 | 小龙主Agent | 定时/按需 |
| **系统日志** | 记录每次任务操作的全链路日志 | 系统自动 | 实时 |

### 8.3 记忆库同步

每次任务闭环后，自动记录以下信息到团队记忆库：

| 记录项 | 内容 | 用途 |
|:------:|------|:----:|
| 任务ID与标题 | 如 `task_20260618_001 - P95延迟排查` | 追溯标识 |
| 执行子代理 | 如 `产品经理Agent` | 责任归属 |
| 产出文件路径 | 如 `AI团队/工作成果/...` | 成果定位 |
| 审核结论 | 通过/驳回及原因 | 质量评估 |
| 关键经验/教训 | 可复用的经验总结 | 知识沉淀 |

## 3. 任务分配规范

### 3.1 任务创建标准

小龙主Agent在分配任务时，必须包含以下信息：

| 字段 | 必填 | 说明 |
|:----:|:----:|------|
| **任务标题** | ✅ | 清晰描述任务内容，如「【加急】P95延迟过高排查与优化」 |
| **任务描述** | ✅ | 详细说明任务目标、背景、交付物要求 |
| **目标子代理** | ✅ | 指定由哪个子代理执行（CTO/安全审计/产品经理/工程师） |
| **优先级** | ✅ | P0-紧急 / P1-高 / P2-中 / P3-低 |
| **截止时间** | ✅ | 明确交付截止日期 |
| **依赖关系** | 可选 | 前置任务或关联任务说明 |
| **参考材料** | 可选 | 相关文档、代码、数据等参考链接 |

### 3.2 任务分配方式

小龙主Agent通过**任务系统**分配任务，子代理通过以下工具链获取：

```
小龙主Agent → 创建任务 → 任务系统
                            ↓
子代理: check_pending_tasks → 发现任务
                            ↓
子代理: claim_task → 领取任务
                            ↓
子代理: 执行任务 → write_file(产出文件) → complete_claimed_task(回调)
```

### 3.3 任务分配原则

1. **单一职责原则**：一个任务只分配给一个子代理，避免多头负责
2. **能力匹配原则**：根据子代理的专业技能分配对应类型任务
3. **负载均衡原则**：避免同一子代理同时承担过多高优任务
4. **依赖有序原则**：有依赖关系的任务按顺序分配

## 4. 子代理执行规范

### 4.1 子代理标准执行流程

每个子代理在被激活后，必须遵循以下工作闭环：

```
STEP 1: check_pending_tasks    ← 每次激活第一件事
            ↓
STEP 2: claim_task             ← 领取任务（可自动分配最高优先级任务）
            ↓
STEP 3: 执行任务
   ├── read_file              ← 读取已有资料
   ├── kb_search/query_*      ← 查询知识库和经验库
   ├── query_pitfalls         ← 查避坑指南（建议先查）
   └── 专业技能工具            ← 使用专业工具完成核心工作
            ↓
STEP 4: write_file            ← 将成果写入 AI团队/工作成果/ 目录
            ↓
STEP 5: complete_claimed_task ← 必调！回调小龙主Agent
   ├── taskId                 ← 领取的任务ID
   ├── result                 ← 执行结果摘要
   └── success                ← true/false
            ↓
STEP 6: 回到STEP 1            ← 循环检查下一个待办任务
```

| **规范性** | 文件命名、格式是否符合规范 | 符合规范 |
| **可读性** | 内容是否清晰、结构化 | 便于后续查阅 |
| **可执行性** | 方案/建议是否具备落地条件 | 有明确实施路径 |

### 6.3 归档要求

审核通过后，小龙主Agent需：

1. **确认归档**：在任务系统中标记任务为「已完成」
2. **记录经验**：将关键经验写入避坑指南（`add_pitfall`）
3. **更新知识库**：将可复用的知识更新到团队知识库
4. **通知相关方**：如有需要，通知关联任务的子代理

## 7. 异常处理机制

### 7.1 子代理超时/卡住

| 场景 | 处理方式 |
|:----:|----------|
| 子代理超过截止时间未完成 | 小龙主Agent发送催办通知，同时评估是否需要重新分配 |
| 子代理连续3次未响应 | 标记为异常状态，由小龙主Agent介入排查 |
| 子代理执行失败 | 在 `complete_claimed_task` 中设置 `success=false` 并说明原因 |
| 工具调用异常 | 记录到避坑指南（`add_pitfall`），尝试替代方案 |

### 7.2 任务冲突

| 场景 | 处理方式 |
|:----:|----------|
| 同一子代理被分配2个以上P0任务 | 子代理主动向小龙主Agent汇报，协商优先级 |
| 多个子代理需要协作 | 小龙主Agent创建主任务+子任务，分别分配 |
| 任务依赖链过长 | 小龙主Agent拆分为多个独立可并行任务 |

### 7.3 成果质量不达标

| 场景 | 处理方式 |
|:----:|----------|
| 首次驳回 | 小龙主Agent明确驳回原因和改进要求 |
| 二次驳回 | 小龙主Agent介入指导或重新分配 |
| 三次驳回 | 升级处理，由小龙主Agent直接完成或更换执行人 |

## 8. 全链路追踪机制

### 8.1 任务状态流转

```
待领取 → 执行中 → 已提交 → 审核中 → 已完成（通过）
                                  → 已驳回（返回执行中）
```

### 8.2 追踪方式

| 追踪方式 | 说明 | 频率 |
|:--------:|------|:----:|
| **check_pending_tasks** | 子代理自查待办任务 | 每次激活时 |
| **complete_claimed_task回调** | 自动通知小龙主Agent | 每次提交时 |
| **小龙主Agent巡检** | 主动检查所有子代理任务进度 | 定时/按需 |

### 8.3 日志记录

每次任务闭环后，自动记录以下信息到团队记忆库：

- 任务ID与标题
- 执行子代理
- 产出文件路径
- 审核结论
- 关键经验/教训
