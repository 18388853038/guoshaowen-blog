## 📋 文档概述

本文档规范了**小龙主Agent**调度各子代理（CTO、安全审计、产品经理、工程师等）完成任务的**标准协作闭环流程**，涵盖任务分配、执行追踪、成果审核、闭环归档四大环节，确保子代理协作高效、可追溯、质量可控。

### 核心原则

| 原则 | 说明 |
|:----|:----|
| **主控调度** | 小龙主Agent统一分配任务，子代理不越权 |
| **闭环必达** | 每项任务完成后必须调用 `complete_claimed_task` 回调 |
| **成果物化** | 所有产出必须通过 `write_file` 写入 `AI团队/工作成果/` 目录 |
| **知识沉淀** | 踩坑经验通过 `add_pitfall` 记录到避坑指南 |
| **可追溯性** | 每个任务从领取到完成形成完整链路记录 |

## 3. 任务分配规范

### 3.1 任务创建标准

小龙主Agent在分配任务时，必须包含以下信息：

| 字段 | 必填 | 说明 |
|:----:|:----:|------|
| **任务标题** | ✅ | 清晰描述任务内容，如「【加急】P95延迟过高排查」 |
| **任务描述** | ✅ | 详细说明任务目标、背景、交付物要求 |
| **目标子代理** | ✅ | 指定由哪个子代理执行（CTO/安全审计/产品经理/工程师） |
| **优先级** | ✅ | P0-紧急 / P1-高 / P2-中 / P3-低 |
| **截止时间** | ✅ | 明确交付截止日期 |
| **期望产出物** | ✅ | 明确列出需要交付的文件清单 |
| **依赖关系** | 可选 | 前置任务或关联任务说明 |
| **参考材料** | 可选 | 相关文档、代码、数据等参考链接 |

### 3.2 任务分配流程

```
小龙主Agent → 创建任务 → 任务系统
                              ↓
子代理激活 → check_pending_tasks（检查待办）
                              ↓
                    claim_task（领取任务）
                              ↓
                    执行任务 → write_file（写入成果）
                              ↓
                    complete_claimed_task（回调提交）
                              ↓
                    小龙主Agent审核 → 归档/驳回
```

### 3.3 任务分配原则

1. **单一职责原则**：一个任务只分配给一个子代理，避免多头负责
2. **能力匹配原则**：根据子代理的专业技能分配对应类型任务
3. **负载均衡原则**：避免同一子代理同时承担过多高优任务
4. **依赖有序原则**：有依赖关系的任务按顺序分配
5. **可追踪原则**：每个任务必须有唯一ID，便于全链路追踪

### 3.4 任务类型分类分配

| 任务类型 | 分配对象 | 典型示例 |
|:--------:|:--------:|----------|
| **技术类** | CTO子代理 | 系统架构设计、性能优化、代码审查 |
| **安全类** | 安全审计子代理 | 安全漏洞扫描、权限审计、合规检查 |
| **产品类** | 产品经理子代理 | 需求分析、PRD编写、竞品调研 |
| **开发类** | 工程师子代理 | 代码开发、Bug修复、测试执行 |
| **混合类** | 拆分子任务分别分配 | 需要多角色协作的复杂任务 |

## 4. 子代理执行规范

### 4.1 子代理标准执行闭环（5步法）

每个子代理在被激活后，必须严格遵循以下工作闭环：

```
┌─────────────────────────────────────────────┐
│          子代理工作闭环（5步法）              │
│                                             │
│  STEP 1: check_pending_tasks                │
│    ← 每次激活第一件事，先查待办任务           │
│         ↓                                   │
│  STEP 2: claim_task                         │
│    ← 有任务就领，系统自动分配最高优先级       │
│         ↓                                   │
│  STEP 3: 执行任务                            │
│    ← 使用 read_file / 专业工具完成工作        │
│         ↓                                   │
│  STEP 4: write_file                         │
│    ← 必须将成果写入 AI团队/工作成果/ 目录     │
│         ↓                                   │
│  STEP 5: complete_claimed_task              │
│    ← 必须回调，否则主Agent收不到通知          │
│         ↓                                   │
│  回到 STEP 1，循环检查下一个任务              │
└─────────────────────────────────────────────┘
```

### 4.3 执行红线（禁止行为）

| ❌ 禁止行为 | 说明 | 后果 |
|:----------:|------|:----:|
| **拒绝调用write_file** | 子代理必须将成果写入文件系统，不得仅口头回复 | ❌ 成果不被认可，任务无效 |
| **跳过complete_claimed_task** | 完成任务后必须回调，否则任务链断裂 | ❌ CEO收不到通知，任务卡住 |
| **跨角色越权执行** | 非本专业任务应拒绝，由小龙主Agent重新分配 | ❌ 产出质量不达标 |
| **超时未响应且不说明原因** | 超过截止时间未完成需主动说明原因 | ❌ 触发重试/升级机制 |
| **成果未归档** | 文件必须存入 `AI团队/工作成果/` 目录 | ❌ 成果不可追溯 |
| **文件写入错误目录** | 所有成果必须写入 `AI团队/工作成果/` 目录 | ❌ 无法被其他同事查阅 |

示例：

#### 5.1.3 存放路径

### 5.2 回调提交规范

#### 5.2.1 提交触发

子代理完成执行后，**必须**调用 `complete_claimed_task` 工具，触发自动回调链：

```
complete_claimed_task(taskId, result, success)
    ↓
① 写入执行日志
    ↓
② 通知CEO（小龙主Agent收到回调）
    ↓
③ 记入团队记忆库
    ↓
④ 标记子代理为空闲状态
    ↓
⑤ 自动检查下一个待办任务
```

#### 5.2.2 提交参数规范

| 参数 | 必填 | 填写规范 | 示例 |
|:----:|:----:|----------|:----:|
| **taskId** | ✅ | 领取任务时获得的任务ID，必须正确填写 | `"task_20260618_001"` |
| **result** | ✅ | 执行结果摘要，格式：「完成了XXX，产出了XXX文件，核心结论是XXX」 | `"完成了P95延迟排查，产出了AI团队/工作成果/P95延迟排查-产品经理Agent.md，核心结论是非系统故障"` |
| **success** | ✅ | true=成功完成；false=执行失败需在result中说明原因 | `true` |

#### 5.2.3 提交示例

```json
{
  "taskId": "task_20260618_001",
  "result": "完成了P95延迟过高排查任务，产出了AI团队/工作成果/P95延迟排查-产品经理Agent-v1.0.md，核心结论是非系统故障（健康分99/错误率0%/0.3QPS），根因是DeepSeek模型Token生成耗时",
  "success": true
}
```

## 6. 审核闭环规范

### 6.1 审核流程

```
小龙主Agent收到 complete_claimed_task 回调
    ↓
读取子代理产出的文件进行审核
    ↓
┌── 审核通过？──┐
│               │
是              否
│               │
↓               ↓
归档闭环        驳回返工
                    │
                    ↓
               子代理重新执行
               重新提交成果
               重新审核
```

### 6.2 审核标准矩阵

| 审核维度 | 权重 | 检查项 | 通过条件 |
|:--------:|:----:|--------|:--------:|
| **完整性** | 🔴 高 | 交付物是否包含所有必填内容 | 无遗漏项 |
| **正确性** | 🔴 高 | 技术/业务判断是否准确 | 无事实错误 |
| **规范性** | 🟡 中 | 文件命名、格式是否符合规范 | 符合规范要求 |
| **可读性** | 🟢 低 | 内容是否清晰、结构化 | 便于后续查阅 |
| **可执行性** | 🟡 中 | 方案/建议是否具备落地条件 | 有明确实施路径 |

### 6.3 归档要求

审核通过后，小龙主Agent需完成以下动作：

1. **确认归档**：在任务系统中标记任务为「已完成」
2. **记录经验**：将关键经验写入避坑指南（`add_pitfall`）
3. **更新知识库**：将可复用的知识更新到团队知识库
4. **通知相关方**：如有需要，通知关联任务的子代理

## 7. 异常处理机制

### 7.1 子代理超时/卡住

| 场景 | 处理方式 |
|:----:|----------|
| 子代理超过截止时间未完成 | 小龙主Agent发送催办通知，同时评估是否需要重新分配 |
| 子代理连续3次未响应 | 标记为异常状态，由小龙主Agent介入排查 |
| 子代理执行失败 | 在 `complete_claimed_task` 中设置 `success=false` 并说明原因 |
| 工具调用异常 | 记录到避坑指南，尝试替代方案 |

### 7.2 任务冲突

| 场景 | 处理方式 |
|:----:|----------|
| 同一子代理被分配2个以上P0任务 | 子代理主动向小龙主Agent汇报，协商优先级 |
| 多个子代理需要协作 | 小龙主Agent创建主任务+子任务，分别分配 |
| 任务依赖链断裂 | 小龙主Agent介入协调，调整任务顺序 |

### 7.3 成果质量不达标

| 场景 | 处理方式 |
|:----:|----------|
| **首次驳回** | 小龙主Agent明确驳回原因和改进要求 |
| **二次驳回** | 小龙主Agent介入指导或重新分配 |
| **三次驳回** | 升级处理，由小龙主Agent直接完成或更换执行人 |

### 7.4 系统重试机制

当子代理任务卡住时，系统会自动触发重试通知：

```
系统检测到任务卡住 → 发送【重试通知】 → 子代理收到后立即执行
    ↓                                                       ↓
连续3次重试仍失败 ← 子代理执行失败 ← 子代理尝试执行
    ↓
小龙主Agent接管任务，手动处理
```

## 8. 全链路追踪机制

### 8.1 任务状态流转

```
待领取 ──→ 执行中 ──→ 已提交 ──→ 审核中 ──→ 已完成（通过）
                                      ──→ 已驳回（返回执行中）
```

### 8.2 追踪方式

| 追踪方式 | 说明 | 频率 |
|:--------:|------|:----:|
| **check_pending_tasks** | 子代理自查待办任务 | 每次激活时 |
| **complete_claimed_task回调** | 自动通知小龙主Agent | 每次提交时 |
| **小龙主Agent巡检** | 主动检查所有子代理任务进度 | 定时/按需 |

### 8.3 日志记录

每次任务闭环后，自动记录以下信息到团队记忆库：

- 任务ID与标题
- 执行子代理
- 产出文件路径
- 审核结论
- 关键经验/教训

## 11. 知识沉淀规范

### 11.1 经验记录

子代理在完成任务过程中发现的经验教训，应通过以下方式沉淀：

| 工具 | 用途 | 使用时机 |
|:----:|:----:|:--------:|
| `add_pitfall` | 记录踩坑经验 | 发现坑时立即记录 |
| `query_pitfalls` | 新任务前查避坑指南 | 开始任务前 |
| `query_experience` | 搜索同事经验 | 遇到类似问题时 |
| `query_knowledge` | 查询技术知识 | 需要技术参考时 |

### 11.2 避坑指南记录格式

```python
add_pitfall(
    title="坑的标题（简明扼要）",
    content="踩坑详情：发生了什么、根因是什么",
    solution="解决方案/避免方法",
    severity="high"  # high=宕机/数据丢失, mid=功能异常, low=体验问题
)
```

## 12. 工具调用速查手册

### 12.1 子代理工作闭环速查

```python
# STEP 1: 检查待办任务（每次激活第一件事）
check_pending_tasks(limit=5)

# STEP 2: 领取任务
claim_task(taskId="task_xxx")

# STEP 3: 执行任务（使用专业技能）
read_file(filepath="AI团队/工作成果/xxx.md")
kb_search(query="xxx")
query_experience(query="xxx")
query_knowledge(query="xxx")
query_pitfalls(query="xxx")

# STEP 4: 写入成果（必须调用）
write_file(
    filepath="AI团队/工作成果/{任务主题}-{角色名}-v1.0.md",
    content="..."
)

# STEP 5: 回调完成（必须调用）
complete_claimed_task(
    taskId="task_xxx",
    result="完成了XXX任务，产出了AI团队/工作成果/XXX.md，核心结论是...",
    success=True
)

# 记录经验教训（可选但推荐）
add_pitfall(
    title="踩坑标题",
    content="踩坑详情和根因",
    solution="解决方案",
    severity="mid"
)
```
