# 子代理协作闭环使用规范文档

> **编写者**：产品经理Agent  
> **编写日期**：2026/06/18  
> **所属公司**：eCompany-Claw · AI 虚拟公司（V3.0）  
> **适用范围**：小龙主Agent调度CTO/安全审计/产品经理子代理的标准流程

---

## 1. 概述

本规范文档定义了**小龙主Agent**调度各子代理（CTO、安全审计、产品经理）进行协作闭环的标准流程。旨在确保任务分配清晰、执行规范、成果可追溯、闭环可验证。

### 1.1 核心原则

| 原则 | 说明 |
|:----|:----|
| **主控调度** | 小龙主Agent统一分配任务，子代理不越权 |
| **闭环必达** | 每项任务完成后必须调用 `complete_claimed_task` 回调 |
| **成果物化** | 所有产出必须通过 `write_file` 写入 `AI团队/工作成果/` 目录 |
| **知识沉淀** | 踩坑经验通过 `add_pitfall` 记录到避坑指南 |
| **可追溯性** | 每个任务从领取到完成形成完整链路记录 |

## 3. 标准协作流程

### 3.1 流程图（文字描述）

```
┌─────────────────────────────────────────────────────────┐
│                  小龙主Agent（调度中心）                    │
│  ① 接收任务 → ② 分析任务类型 → ③ 分配子代理              │
└─────────────────────────────────────────────────────────┘
                              │
          ┌───────────────────┼───────────────────┐
          ▼                   ▼                   ▼
   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
   │ 产品经理Agent│   │   CTO子代理  │   │ 安全审计Agent│
   │ 需求分析/PRD │   │ 技术方案/审查│   │ 安全评估/审计│
   └─────────────┘   └─────────────┘   └─────────────┘
          │                   │                   │
          └───────────────────┼───────────────────┘
                              ▼
               ┌─────────────────────────────┐
               │    小龙主Agent（成果汇总）     │
               │  ④ 审查成果 → ⑤ 回调CEO      │
               │  ⑥ 归档 → ⑦ 记入记忆库       │
               └─────────────────────────────┘
```

### 3.2 详细步骤

#### 阶段一：任务分配（小龙主Agent）

1. **任务创建**：小龙主Agent在任务系统中创建待办任务
2. **任务描述**：包含任务标题、详细描述、优先级、期望产出物清单
3. **分配方式**：通过 `check_pending_tasks` → `claim_task` 机制由子代理主动领取

#### 阶段二：任务执行（子代理）

1. **检查任务**：子代理激活后第一件事调用 `check_pending_tasks`
2. **领取任务**：调用 `claim_task` 领取任务
3. **执行任务**：
   - 使用 `read_file` 查看已有资料
   - 使用 `kb_search` / `query_experience` / `query_knowledge` / `query_pitfalls` 查询知识库
   - 使用专业工具（如 `req_analysis`、`code_review`、`security_audit` 等）完成本职工作
   - **必须调用 `write_file` 将成果写入 `AI团队/工作成果/` 目录**
4. **回调完成**：调用 `complete_claimed_task` 通知小龙主Agent

#### 阶段三：成果汇总（小龙主Agent）

1. **接收回调**：系统自动通知小龙主Agent
2. **审查成果**：读取子代理产出的文件进行审查
3. **汇总汇报**：将各子代理成果整合，向CEO汇报
4. **归档沉淀**：将关键经验记入记忆库和避坑指南

## 6. 工具调用规范

### 6.1 子代理工作闭环

```
STEP 1 → check_pending_tasks    // 每次激活先查任务
STEP 2 → claim_task             // 有任务就领
STEP 3 → 执行任务（读/写文件）   // 使用专业工具完成工作
STEP 4 → complete_claimed_task  // 必须调用，通知主Agent
STEP 5 → 回到STEP 1             // 循环检查下一个任务
```

### 6.2 必须调用的工具

| 场景 | 必调工具 | 说明 |
|:----|:----|:----|
| 任务领取 | `claim_task` | 不领取无法执行 |
| 读取资料 | `read_file` | 查看已有成果和资料 |
| 写入成果 | `write_file` | **必须调用，否则成果无效** |
| 任务完成 | `complete_claimed_task` | **必须调用，否则主Agent收不到通知** |
| 知识查询 | `kb_search` / `query_experience` / `query_knowledge` / `query_pitfalls` | 充分利用团队积累 |
| 避坑记录 | `add_pitfall` | 发现坑时记录，供全员参考 |

### 6.3 禁止行为

- ❌ 禁止不调用 `write_file` 仅在对话中输出成果
- ❌ 禁止不调用 `complete_claimed_task` 就结束任务
- ❌ 禁止越权操作（如产品经理直接修改生产代码）
- ❌ 禁止将文件写入非 `AI团队/工作成果/` 目录

## 7. 异常处理机制

### 7.1 任务卡住/超时

| 异常场景 | 处理方式 |
|:----|:----|
| 子代理长时间未响应 | 小龙主Agent发送重试通知 |
| 子代理执行失败 | 在 `complete_claimed_task` 中设置 `success=false` 并说明原因 |
| 连续3次重试失败 | 小龙主Agent接管任务，手动处理 |
| 工具调用异常 | 记录到避坑指南，尝试替代方案 |

### 7.2 成果质量不达标

1. 小龙主Agent审查发现质量问题
2. 在回调中附加审查意见
3. 创建修订任务重新分配给子代理
4. 子代理修订后重新提交

## 8. 记忆与知识沉淀

### 8.1 经验记录

子代理在完成任务过程中发现的经验教训，应通过以下方式沉淀：

- **`add_pitfall`**：记录踩坑经验（严重度：high/mid/low）
- **`query_pitfalls`**：新任务开始前先查避坑指南

### 8.2 记忆库同步

`complete_claimed_task` 回调完成后，系统自动触发：
1. 写入执行日志
2. 通知CEO
3. 记入记忆库
4. 标记子代理为空闲状态
5. 自动检查下一个待办任务
