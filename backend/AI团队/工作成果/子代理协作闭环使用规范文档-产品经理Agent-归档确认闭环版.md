## 📋 文档概述

本文档规范了**小龙主Agent**调度各子代理（CTO、安全审计、产品经理、工程师等）完成任务的**标准协作闭环流程**，涵盖任务分配、执行追踪、成果审核、闭环归档四大环节，确保子代理协作高效、可追溯、质量可控。

### 核心原则

| 原则 | 说明 | 违反后果 |
|:----|:----|:---------|
| **主控调度** | 小龙主Agent统一分配任务，子代理不越权 | ❌ 任务无效，需重新分配 |
| **闭环必达** | 每项任务完成后必须调用 `complete_claimed_task` 回调 | ❌ 任务链断裂，CEO收不到通知 |
| **成果物化** | 所有产出必须通过 `write_file` 写入 `AI团队/工作成果/` 目录 | ❌ 成果不被认可 |
| **知识沉淀** | 踩坑经验通过 `add_pitfall` 记录到避坑指南 | ❌ 团队无法复用经验 |
| **可追溯性** | 每个任务从领取到完成形成完整链路记录 | ❌ 无法回溯问题根因 |

```
┌──────────────────────────────────────────────────────────────────────┐
│                    子代理协作闭环全流程                                │
│                                                                      │
│  ① 任务分配 ──→ ② 子代理执行 ──→ ③ 成果提交 ──→ ④ 小龙审核         │
│      ↑                                               │              │
│      └─────────── ⑤ 归档/返工 ←───── ④ 审核不通过 ────┘             │
│                                                                      │
│  [阶段详解]                                                           │

│  ⑤ = 通过→归档闭环；驳回→返回②修订                                   │

```

## 3. 任务分配规范

### 3.1 任务创建标准

小龙主Agent在分配任务时，必须包含以下信息：

| 字段 | 必填 | 说明 | 示例 |
|:----:|:----:|------|:----:|
| **任务标题** | ✅ | 清晰描述任务内容，建议加优先级标签 | `【加急】P95延迟过高排查与优化` |
| **任务描述** | ✅ | 详细说明任务目标、背景、交付物要求 | `排查P95延迟7809ms根因...` |
| **目标子代理** | ✅ | 指定由哪个子代理执行 | `CTO子代理` |
| **优先级** | ✅ | P0-紧急 / P1-高 / P2-中 / P3-低 | `P0` |
| **截止时间** | ✅ | 明确交付截止日期 | `今天18:00前` |
| **期望产出物** | ✅ | 明确列出需要交付的文件清单 | `1.排查报告 2.优化方案` |
| **依赖关系** | 可选 | 前置任务或关联任务说明 | `依赖安全审计完成` |
| **参考材料** | 可选 | 相关文档、代码、数据等参考链接 | `参考AI团队/工作成果/...` |

### 3.2 任务分配流程

```
小龙主Agent
    │
    ├─ ① 分析任务类型
    │   ├─ 技术类 → 分配CTO子代理
    │   ├─ 安全类 → 分配安全审计子代理
    │   ├─ 产品类 → 分配产品经理子代理
    │   ├─ 开发类 → 分配工程师子代理
    │   └─ 混合类 → 拆分子任务分别分配
    │
    ├─ ② 创建任务（含完整描述字段）
    │   └─ 任务系统接收并存储
    │
    ├─ ③ 等待子代理领取
    │   └─ 子代理通过 check_pending_tasks 发现任务
    │
    └─ ④ 确认子代理已领取
        └─ 子代理通过 claim_task 确认任务归属
```

### 3.3 分配原则

| 原则 | 说明 |
|:----:|------|
| **单一职责** | 一个任务只分配给一个子代理，避免多头负责 |
| **能力匹配** | 根据子代理的专业技能分配对应类型任务 |
| **负载均衡** | 避免同一子代理同时承担过多高优任务 |
| **依赖有序** | 有依赖关系的任务按顺序分配 |
| **可追踪** | 每个任务必须有唯一ID，便于全链路追踪 |

## 4. 子代理执行规范

### 4.1 子代理标准工作闭环（5步法）

每个子代理被激活后，必须严格遵循以下闭环流程：

```
┌─────────────────────────────────────────────────────┐
│              子代理工作闭环（5步法）                   │
│                                                     │
│  STEP 1: check_pending_tasks                        │
│  【每次激活第一件事】检查是否有待办任务                │
│           ↓                                         │
│  STEP 2: claim_task                                 │
│  【领取任务】确认任务归属，获取任务详情                │
│           ↓                                         │
│  STEP 3: 执行任务                                    │
│  【使用专业技能工具完成工作】                          │
│  - read_file 查看已有资料                            │
│  - kb_search / query_experience 查知识库             │
│  - 使用专业工具（req_analysis/code_review等）         │
│           ↓                                         │
│  STEP 4: write_file                                 │
│  【必须调用！将成果写入文件系统】                     │
│  路径：AI团队/工作成果/                              │
│           ↓                                         │
│  STEP 5: complete_claimed_task                      │
│  【必须调用！回调小龙主Agent】                       │
│  参数：taskId + result + success                    │
│           ↓                                         │
│  回到 STEP 1，循环检查下一个任务                      │
└─────────────────────────────────────────────────────┘
```

### 4.3 执行红线（禁止行为）

| ❌ 禁止行为 | 说明 | 后果 |
|:----------:|------|:----:|
| **拒绝调用write_file** | 子代理必须将成果写入文件系统，不得仅口头回复 | ❌ 成果不被认可，任务无效 |
| **跨角色越权执行** | 非本专业任务应拒绝，由小龙主Agent重新分配 | ❌ 产出质量不达标 |
| **跳过complete_claimed_task** | 完成任务后必须回调，否则任务链断裂 | ❌ CEO收不到通知，任务卡住 |
| **超时未响应且不说明原因** | 超过截止时间未完成需主动说明原因 | ❌ 触发重试/升级机制 |
| **文件写入错误目录** | 所有成果必须写入 `AI团队/工作成果/` 目录 | ❌ 成果不可追溯 |

## 5. 成果提交规范

### 5.1 成果文件规范

#### 5.1.1 文件头部元信息

每份产出文档必须包含以下头部信息：

```markdown
---
# 写入者: {角色名} ({agent-id})
# 写入时间: {当前时间}
---

> **编写者**：{角色名}
> **编写日期**：{当前时间}
> **所属公司**：eCompany-Claw · AI 虚拟公司（V3.0）
> **关联任务**：{任务标题或ID}
```

#### 5.1.2 文件命名规范

```
格式：{任务主题}-{子代理角色名}(-v{版本}).md

示例：
  P95延迟过高排查与优化-CTO子代理.md
  安全合规审查-安全审计Agent.md
  用户需求分析-产品经理Agent.md
  子代理协作闭环使用规范文档-产品经理Agent-归档确认闭环版.md
```

#### 5.1.3 存放路径

所有文件统一存放于：**`AI团队/工作成果/`** 目录下

### 5.2 回调提交规范

#### 5.2.1 提交触发

子代理完成执行后，**必须**调用 `complete_claimed_task` 工具，触发自动回调链：

```
complete_claimed_task(taskId, result, success)
    ↓
① 写入执行日志
    ↓
② 通知CEO（小龙主Agent收到回调）
    ↓
③ 记入团队记忆库
    ↓
④ 标记子代理为空闲状态
    ↓
⑤ 自动检查下一个待办任务
```

#### 5.2.2 提交参数规范

| 参数 | 必填 | 填写规范 | 示例 |
|:----:|:----:|----------|:----:|
| **taskId** | ✅ | 领取任务时获得的任务ID，必须正确填写 | `"task_20260618_001"` |
| **result** | ✅ | 执行结果摘要，格式：「完成了XXX，产出了XXX文件，核心结论是XXX」 | `"完成了P95延迟排查，产出了AI团队/工作成果/P95延迟排查-产品经理Agent.md，核心结论是非系统故障"` |
| **success** | ✅ | `true`=成功完成；`false`=执行失败需在result中说明原因 | `true` |

#### 5.2.3 提交示例

```json
{
  "taskId": "task_20260618_001",
  "result": "完成了P95延迟过高排查任务，产出了AI团队/工作成果/P95延迟排查-产品经理Agent.md，核心结论：健康分99+错误率0%+0.3QPS低流量，排除系统故障",
  "success": true
}
```

## 6. 审核闭环规范

### 6.1 审核流程

```
小龙主Agent收到 complete_claimed_task 回调
    │
    ├─ ① 读取子代理产出的文件（read_file）
    │
    ├─ ② 对照任务要求进行审核
    │   ├─ 完整性检查：交付物是否齐全
    │   ├─ 正确性检查：结论是否准确
    │   ├─ 规范性检查：格式是否符合要求
    │   └─ 可执行性检查：建议是否可落地
    │
    ├─ ③ 做出审核决策
    │   ├─ ✅ 通过 → 进入归档环节
    │   └─ ❌ 驳回 → 创建修订任务，返回子代理
    │
    └─ ④ 归档沉淀
        ├─ 标记任务为「已完成」
        ├─ 记录关键经验到避坑指南（add_pitfall）
        ├─ 更新团队知识库
        └─ 向CEO汇总汇报
```

### 6.2 审核标准矩阵

| 审核维度 | 权重 | 检查项 | 通过条件 |
|:--------:|:----:|--------|:--------:|
| **完整性** | 🔴 高 | 交付物是否包含所有必填内容 | 无遗漏项 |
| **正确性** | 🔴 高 | 技术/业务判断是否准确 | 无事实错误 |
| **规范性** | 🟡 中 | 文件命名、格式是否符合规范 | 符合规范要求 |
| **可读性** | 🟡 中 | 内容是否清晰、结构化 | 便于后续查阅 |
| **可执行性** | 🟢 低 | 方案/建议是否具备落地条件 | 有明确实施路径 |

### 6.3 驳回与返工机制

| 驳回次数 | 处理方式 |
|:--------:|----------|
| **首次驳回** | 小龙主Agent明确驳回原因和改进要求，子代理修订后重新提交 |
| **二次驳回** | 小龙主Agent介入指导或调整任务要求 |
| **三次驳回** | 升级处理，由小龙主Agent直接完成或更换执行人 |

## 7. 异常处理机制

### 7.1 子代理超时/卡住

| 场景 | 处理方式 |
|:----:|----------|
| 子代理超过截止时间未完成 | 小龙主Agent发送催办通知，同时评估是否需要重新分配 |
| 子代理连续3次未响应 | 标记为异常状态，由小龙主Agent介入排查 |
| 子代理执行失败 | 在 `complete_claimed_task` 中设置 `success=false` 并说明原因 |
| 工具调用异常 | 记录到避坑指南（add_pitfall），尝试替代方案 |

### 7.2 任务冲突

| 场景 | 处理方式 |
|:----:|----------|
| 同一子代理被分配2个以上P0任务 | 子代理主动向小龙主Agent汇报，协商优先级 |
| 多个子代理需要协作 | 小龙主Agent创建主任务+子任务，分别分配 |
| 任务依赖链断裂 | 小龙主Agent介入协调，调整任务顺序 |

### 7.3 系统重试机制

当子代理任务卡住时，系统会自动触发重试通知：

```
系统检测到任务卡住
    ↓
发送【重试通知】给子代理
    ↓
子代理收到后立即执行任务
    ↓
┌── 执行成功？──┐
│               │
是              否（连续3次重试仍失败）
│               │
↓               ↓
任务闭环完成    小龙主Agent接管任务，手动处理
```

## 8. 全链路追踪机制

### 8.1 任务状态流转

```
待领取 ──→ 执行中 ──→ 已提交 ──→ 审核中 ──→ ✅ 已完成（通过）
                                      ──→ 🔄 已驳回（返回执行中）
```

### 8.2 追踪方式

| 追踪方式 | 说明 | 频率 |
|:--------:|------|:----:|
| **check_pending_tasks** | 子代理自查待办任务 | 每次激活时 |
| **complete_claimed_task** | 回调链自动记录执行日志 | 每次任务完成时 |
| **write_file** | 成果文件作为永久记录 | 每次产出时 |
| **add_pitfall** | 踩坑经验沉淀到避坑指南 | 遇到问题时 |

### 8.3 文件归档清单
