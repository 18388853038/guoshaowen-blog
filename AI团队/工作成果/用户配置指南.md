## 1. AI 模型配置

**用途：** 配置系统使用的 AI 模型、API Key 和路由策略。
**访问路径：** 系统设置页面 → AI 模型区域

### 1.1 选择主模型（默认模型）

| 配置项 | 说明 |
|--------|------|
| 提供商 (provider) | deepseek（推荐）、openai、claude、gemini、openrouter 等 18+ 供应商 |
| 模型 (model) | 每个提供商下的具体模型 ID（如 `deepseek-chat`、`gpt-4o`） |
| API Key | 对应提供商的 API 密钥 |
| API Base URL | 自定义 API 端点（从预置列表自动选择，也可手动修改） |

**AI 操作步骤：**

```
1. 设置提供商: POST /api/v4/settings/provider { provider: "deepseek" }
2. 设置模型: POST /api/v4/settings/provider { model: "deepseek-chat" }
3. 设置 API Key: POST /api/v4/settings/apikey { key: "sk-xxx", provider: "deepseek" }
4. 设置 API Base: POST /api/v4/settings/provider { apiBase: "https://api.deepseek.com/v1/chat/completions" }
5. 一键保存全部: POST /api/v4/settings/provider { provider, model, apiKey, apiBase }
6. 测试连接: POST /api/provider/test { provider, model, apiKey, apiBase }
```

**已注册路由：**
- `POST /api/v4/settings/provider` — 保存提供商/模型/apiBase
- `POST /api/v4/settings/apikey` — 保存指定提供商的 API Key
- `GET /api/v4/settings/provider` — 读取当前设置
- `GET /api/v4/settings/apikey` — 读取所有提供商的 Key 状态
- `POST /api/provider/test` — 测试连接
- `GET /api/provider/config` — 读取配置详情
- `GET /api/models/providers` — 获取所有提供商和可用模型列表

### 1.2 多模型路由策略（Multi-Model Router）

| 策略 | 说明 | 图标 |
|------|------|------|
| fixed | 固定使用主模型 | 🎯 |
| fallback | 主模型失败时切换到备用模型 | 🔄 |
| roundrobin | 轮询主模型和备用模型 | 🔁 |
| smart | 根据任务复杂度选择模型 | 🧠 |

**AI 操作步骤：**

```
1. 查询当前路由策略: GET /api/v4/settings/provider/routing
2. 设置路由策略: POST /api/v4/settings/provider/routing { strategy: "fallback" }
3. 添加备用模型: POST /api/v4/settings/provider/routing { addBackup: "gpt-4o-mini" }
4. 移除备用模型: POST /api/v4/settings/provider/routing { removeBackup: "gpt-4o-mini" }
```

## 2. 渠道配置（消息通道）

**用途：** 连接外部消息平台（钉钉、飞书、企微、微信、QQ），让 AI 能从多渠道接收和回复消息。
**访问路径：** 通讯渠道页面

### 2.1 系统内置渠道（无需配置）

| 渠道 | 说明 |
|------|------|
| 🌐 Web Chat | 前端工作台内嵌聊天 |
| 🔌 REST API | HTTP API 接口 |
| 🔗 WebSocket | 实时通道 |

### 2.2 外部渠道（需配置凭证）

| 渠道 | ID | 配置方式 | 典型凭证 |
|------|-----|---------|---------|
| 📱 钉钉 | `dingtalk` | 凭据配置 | AppKey + AppSecret |
| 🏢 企业微信 | `wecom` | 凭据配置 | BotId + BotSecret |
| 📱 微信 | `wechat_ilink` | 扫码绑定 | 二维码扫描 |
| 📘 飞书 | `feishu` | 凭据配置 | AppId + AppSecret |
| 💬 个人微信 | `personal_wx` | 扫码绑定 | 二维码扫描 |
| 🐧 QQ 机器人 | `qqbot` | 凭据配置 或 扫码绑定 | BotAppId + Token |

### 2.3 渠道状态含义

| 状态 | 含义 |
|------|------|
| 🟢 运行中 | 渠道已连接并正常运行 |
| 🔵 已连接 | 配置已保存，连接建立 |
| 🟡 连接中 | 正在尝试连接 |
| 🔴 连接失败 | 配置错误或网络不通 |
| ⚫ 未连接 | 未配置 |

### 2.4 配置工作流

#### 凭据配置类（钉钉/飞书/企微）

**AI 操作步骤：**
```
1. 获取渠道配置模板: GET /api/bindings/channel-types（返回每个渠道的必填字段列表）
2. 保存渠道配置: POST /api/channels/install { channelId: "dingtalk", params: { appKey: "xxx", appSecret: "yyy" } }
3. 查询渠道状态: GET /api/channels（返回所有渠道实时状态）
4. 获取桥接状态: GET /api/wechat/bridge/status（微信专用）
5. 获取桥接状态: GET /api/wecom/bridge/status（企微专用）
6. 断开连接: POST /api/channels/disconnect { channelId: "dingtalk" }
```

#### 扫码绑定类（微信/QQ）

**AI 操作步骤：**
```
1. 获取微信二维码: GET /api/wechat/qrcode → { ok: true, qrcode: "base64..." }
2. 获取 QQ 二维码: GET /api/qqbot/qrcode → { ok: true, image: "base64..." }
3. 轮询绑定状态: GET /api/qqbot/bind/status → { bound: true/false }
4. 刷新二维码: 重复第一步即可
```

### 2.5 渠道消息同步到工作台

渠道消息会自动广播到工作台 Chat 页面。用户只需：
1. 确保渠道已连接（状态 > 绿色/蓝色）
2. 在外部渠道（钉钉/微信等）发送消息
3. 消息会同步显示在工作台聊天列表，格式：`📡 [渠道名] 用户: 消息内容`
4. AI 的回复也会同步显示在工作台

## 3. 边界控制配置

**用途：** 管理 AI Agent 的行为边界——频控、工具权限、白名单/黑名单。
**访问路径：** 边界管理页面

### 3.1 核心配置

| 配置项 | 说明 |
|--------|------|
| 频控 (Rate Limit) | 每分钟/小时最大请求数 |
| 工具黑名单 | 禁用的工具列表（如 `exec_shell`, `web_search`） |
| 白名单 | 允许访问的域名/IP |
| 默认 Agent | 选择默认使用的 AI Agent |

### 3.2 可用工具列表

| 工具 | 说明 | 风险等级 |
|------|------|---------|
| `exec_shell` | 执行 Shell 命令 | 🔴 高 |
| `web_search` | 搜索网页 | 🟡 中 |
| `web_fetch` | 抓取网页内容 | 🟢 低 |
| `file_read` | 读取文件 | 🟢 低 |
| `file_write` | 写入文件 | 🟡 中 |
| `api_call` | 调用外部 API | 🟡 中 |
| `skill_call` | 调用 OpenClaw 技能 | 🟢 低 |
| `chat_memory` | 读写记忆 | 🟢 低 |
| `scheduler` | 定时任务管理 | 🟡 中 |
| `employee_dispatch` | 调度团队成员 | 🟢 低 |

### 3.3 AI 操作步骤

```
1. 获取所有 Agent 列表: GET /api/agents
2. 获取指定 Agent 配置: GET /api/agents/{agentId}
3. 设置频控: POST /api/agents/{agentId}/rate-limit { maxPerMinute: 10, maxPerHour: 200 }
4. 禁用工具: POST /api/agents/{agentId}/tools/disable { tools: ["exec_shell"] }
5. 启用工具: POST /api/agents/{agentId}/tools/enable { tools: ["exec_shell"] }
6. 设置默认 Agent: POST /api/agents/default { agentId: "ceo-agent" }
7. 新增 Agent: POST /api/agents { id, name, description, tools, ... }
8. 保存 Agent 配置: POST /api/agents/{agentId} { id, name, ... }
```

## 4. Harness 系统监控配置

**用途：** 系统健康大盘、SLA 监控、规则管理、任务调度审计。
**访问路径：** Harness 管理页面

### 4.1 大盘指标

| 指标 | API | 说明 |
|------|-----|------|
| 系统健康度 | GET `/api/harness/metrics` | CPU、内存、进程状态等 |
| 任务调度状态 | GET `/api/scheduler` | 定时任务运行状态 |
| SLA 统计 | GET `/api/sla/stats` | 服务等级协议达标率 |
| 规则统计 | GET `/api/rules/stats` | 系统规则触发统计 |
| 错误趋势 | GET `/api/errors/trend` | 错误发生趋势图 |
| 留存率 | GET `/api/keeprate/report` | 任务留存报告 |
| 排行榜 | GET `/api/leaderboard` | 员工/Agent 效率排行 |
| 评审状态 | GET `/api/evaluation/health` | AI 输出质量评审 |

### 4.2 AI 操作步骤

```
1. 获取大盘数据: GET /api/dashboard
2. 获取调度列表: GET /api/scheduler
3. 启用/禁用调度: POST /api/scheduler/{id}/toggle
4. 获取规则列表: GET /api/rules
5. 新增规则: POST /api/rules { name, condition, action }
6. 获取审计日志: GET /api/audit
7. 获取待处理申诉: GET /api/appeals/pending
```

## 5. 工作流配置

**用途：** 创建和调度自动化工作流，如定时检查、自动备份、消息转发。
**访问路径：** 工作流页面（可从导航栏访问）

### 5.1 定时任务类型

| 类型 | 说明 | 示例 |
|------|------|------|
| 定时报告 | 每天固定时间输出报告 | 早8点日报 |
| 定时巡检 | 定期检查系统状态 | 每10分钟检查 |
| 定时备份 | 自动备份配置/数据 | 每天凌晨备份 |
| 定时推送 | 主动推送消息到渠道 | 每整点推送 |

### 5.2 AI 操作步骤

```
1. 获取工作流列表: GET /api/workflows
2. 创建工作流: POST /api/workflows { name, type, cron, action, params }
3. 启用/禁用: POST /api/workflows/{id}/toggle
4. 手动触发: POST /api/workflows/{id}/run
5. 查看运行记录: GET /api/scheduler/runs
```

## 6. 系统高级配置

### 6.1 配置导入/导出

**用途：** 备份和恢复系统配置，或在多个实例间迁移。

**AI 操作步骤：**
```
1. 导出全部配置: POST /api/v4/settings/export → 返回 JSON 配置包
2. 导入配置: POST /api/v4/settings/import { JSON配置对象 }
3. 导入后自动重启系统
```

### 6.2 恢复出厂设置

⚠️ **危险操作，需双重确认！**
- 恢复所有设置到初始状态
- 会清除：AI Key 配置、渠道绑定的凭证
- 不会清除：团队数据、历史记录

**AI 操作步骤：**
```
1. 用户输入确认关键字（默认为 "yes" 或中文"确认"）
2. POST /api/v4/settings/reset { confirm: true }
3. 系统自动重启
```

### 6.3 配置文件路径

| 文件 | 路径 | 说明 |
|------|------|------|
| 服务器配置 | `F:\eCompanyClaw\backend\backend.json` | 主配置文件 |
| 渠道凭证 | `F:\eCompanyClaw\backend\channel-credentials.json` | 渠道凭证（加密存储） |
| Agent 配置 | `F:\eCompanyClaw\backend\agents.json` | Agent 列表和配置 |
| 邮件模板 | `F:\eCompanyClaw\backend\email-templates.json` | 邮件通知模板 |
| 导航配置 | `F:\eCompanyClaw\backend\navigation.json` | 导航栏配置 |
